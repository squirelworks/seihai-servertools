
## Connecting a client

- **Expected client:** the Windows **Graal 5.12** (protocol 24). 4.20r8 and
  the Linux/Mac 4.20r6 link too where the notes above say so. The community
  Frankenstein 6.037 (graal-client-repro) uses the same 5.12 protocol.
- A 5.12 always logs in first to a server it calls "Login", then follows the
  warp that server sends. With seihai-gserver you can be that login server
  yourself: uncomment `lobby_port` in `config/server.txt` and set it to the
  port your client logs in to, and point the client's login host at your
  machine (for example in the hosts file). Or list the server on a
  seihai-listserver.
- A 5.12 enters 3D only on a server whose name starts with `3 `. The
  `name` line in `config/server.txt` already does; keep the `3 ` if you
  rename it.
- The client opens TCP on the listed port (14802 by default) and UDP on that
  port + 1. Open both if the client is on another machine, and set
  `bind = 0.0.0.0` (the default listens on loopback only).
- The Graal 3D community guide (Graal_analysis `graal3d/community-guide.md`)
  has the full set-up, what a player sees at each login step, and
  troubleshooting.

## Known limits on a real 5.12 (all worlds)

From seihai-gserver `docs/GRAAL3D.md`, "Known limits on a real 5.12":

- At most 4,096 ghosts a client; big worlds need `graal3d_scope`.
- No grass or ground cover while the avatar stands within 8 units of the
  world origin on both x and y.
- A world switch into a world with no terrain, water or Sun freezes a 5.12
  on a sky-only frame.
- Frame rates under software rendering (Wine, no GPU) are low in dense
  places; a real GPU does much better.
- Lab captures, client files and logs are not part of this package; it holds
  only the world.
