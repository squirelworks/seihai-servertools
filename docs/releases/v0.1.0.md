The first release of **seihai-servertools**, the Seihai project's tools for running and building Graal servers: lab start-up and setup, checks, LAT level editors, gpak and code tools, a stress rig, and the 3D world tools for seihai-gserver's Graal 3D mode. Built on seihai-core v0.8.0 and seihai-rc v0.2.0. MIT or Apache-2.0.

## 3D tools

- `gen terrain --3d` / `gen 3d`: a height-field or gmap world as a 3D world, with a `.3ds` ground, trees and rocks, and with `--stream` the streamed terrain 4.20r6 and 5.x clients read. `--playerworld` writes a seihai-gserver world that serves as it is; `--v2` gives the GServer-v2 layout.
- `seihai-pw3d`: every level of a 2D playerworld as 3D, with sign boards and a walker weapon. House interiors are placed inside the world they are entered from and joined by `portal` doors, so no door is a world switch (needs seihai-gserver 0.2.0 and `graal3d_scope`).
- `seihai-regions`: split a big overworld into regions, report its density against what a client holds, or build a demo overworld (8,192 units, 6 towns).
- `seihai-asset3d`: glTF/GLB, OBJ, STL and 3DS models and pictures as shapes a 5.12 draws, added to a world.
- `seihai-edit3d`: an offline 3D level editor with a live preview of shapes, terrain and water, plus the same edits from the command line.
- `scripts/community-worlds/build.sh`: the 3D test worlds as reproducible tarballs.
- Checked against a real 5.12 in the lab. Client limits: seihai-gserver `docs/GRAAL3D.md`, "Known limits on a real 5.12" (4,096 ghosts a client; a world switch into a world with no terrain, water or Sun freezes a 5.12).

Interiors (`portal`) and regions (`regions`) need seihai-gserver 0.2.0. The isle terrain and asset worlds also run on seihai-gserver-v2 4.0.0-seihai.6 with the Graal 3D add-on.

## Download and run

Pick the archive for your system: Linux x86_64, Windows x86_64, macOS Intel (x86_64) or macOS Apple Silicon (aarch64), and check it against `SHA256SUMS`. Run `seihai-servertools guide` to see every tool and when to use it. On macOS, the first start may need right-click → Open, because the build is not signed. This is the first run of the four-target release build: any archive missing here failed to build and is listed below.

## Everything in this release

- `seihai-servertools guide [TOPIC]` (also `seihai-guide`, and what `seihai-servertools` prints with no words) explains how the listserver, gservers, NPC-servers and RC fit together, lists every tool with when to use it, and has topics for setup, each server, RC usage and rights, and troubleshooting.
- `setup new` gives a public listserver an allow-list: only the layout's gservers may register, each with its own random HQ password, written as `listserver_hq_password` in the gserver's `config/server.txt` (needs seihai-gserver with that setting, squirelworks/seihai-gserver#212). `allow_list` in `layout.toml` turns it on or off. The guide now shows `seihai-rc nc discover` for NPC Control.
- `setup new [DIR]` writes a server folder from scratch for the seihai-gserver stack: listservers, gservers each pointed at a chosen listserver (or one elsewhere, or none), an NPC-server per gserver (`auto`, `external` with a random token file, or `off`), staff accounts for RC with STAFF, IP range and folder rights and random passwords printed once, and start/stop scripts for Linux, macOS and Windows. It asks step by step, or takes options or a `layout.toml` (`--plan`, `--print-plan`), and refuses a port used twice (a busy one is a warning).
- Every tool is also its own program, built and tested on its own: `seihai-lab`, `seihai-setup`, `seihai-check`, `seihai-code`, `seihai-gpak`, `seihai-level`, `seihai-theme`, `seihai-gmap`, `seihai-gani`, `seihai-gen`, `seihai-stats`, `seihai-gif2mng`, `seihai-servertools-gui` and `seihai-suite-stress` (`tools/README.md`). They take the same words as `seihai-servertools <tool>`, which still works unchanged, and release archives carry them next to it.
- `seihai-suite-stress probe` has two new steps. `want FILE` sends a file request. `expect SECONDS TEXT` fails the run unless a matching server message arrives in time, so a steps file can be a smoke test (seihai-gserver-v2#87).
- Built on seihai-core and seihai-draw v0.7.2, with seihai-rc at a `main` commit on the same core, so the lock file holds one core (it held v0.6.1 and, through seihai-rc, v0.4.0). The LAT NPC-server database page now tokenizes NPC and class scripts in the server's text profile, which seihai-rc reads from the server's `Server:` line.

- Movie previews no longer overflow the word-wrap width calculation when a TEXT actor has an extreme negative horizontal coordinate; ordinary wrapping and partially visible text retain their placement.

- World checks can select a shared client build with `check --client LABEL` or the GUI profile picker; `check --list-clients` lists labels. Selected level/gmap/gani/script capability warnings preserve unknown support and JSON format 1. Default inventory and dependency pins are unchanged; per-build package readability and exact script vocabulary are not certified.

- Saving levels and ganis preserves parsed finite NPC, baddy, link-arrival and sound coordinates outside the i32 range instead of silently narrowing them; ordinary formatting and existing keep-arrival semantics remain unchanged.

- Listserver setup reads valid TOML strings and integers consistently with its editor, preserving quoted account paths, escapes and numeric separators; malformed files retain the existing best-effort fallback.

- Repacking resource packages validates and finishes a temporary output before replacement, preserving an existing package on validation/write refusal and retaining Unix file-creation modes; package and key-file updates remain separate.

- `gen terrain --3d` also writes the world for a Graal 3D server: a `.3ds` ground built from the same height field (one coloured mesh per level), tree and rock shapes, and a `graal3dworld.txt` that places them on the ground with a sun and a spawn point. `--vscale` sets the height scale and `--trees` the placements per level. Not yet loaded by a real 3D client.
- `gen terrain --stream` (implies `--3d`) also writes the ground as streamed terrain for 4.20r6 and 5.x clients. `NAME_terrain/` holds the 256 `heights<x>-<y>.dat` chunk files, `heights.info` (one texture name a line) and four 256 x 256 24-bit textures, and the world file uses seihai-gserver-v2's `terrain` line. Each chunk is written exactly as the client re-encodes it, so the stamps the client sends back match. The format is the one the real 5.12 client was confirmed to read on 2026-11-25 (Graal_analysis `torque/terrain-512.md`). A full generated world has not yet been loaded on a real client.
- `gen 3d GMAP DIR` builds the same 3D world, with `--stream` the streamed terrain too, from any gmap that has a `HEIGHTMAP` block. That covers worlds made earlier with `gen terrain`, and those from the original TerrainGenerator. `GENBASE`, `GENHEIGHT` and `GENSEED` set the water level, the height bands and where trees go.
- `--playerworld` (with `gen terrain` or `gen 3d`; implies `--3d`) now writes a seihai-gserver world that serves as it is with `seihai-gserver --world DIR`: `config/graal3dworld.txt`, the levels and gmap in `levels/`, every 3D file in `files/3d/` under its real, lower-cased name, and a `config/server.txt` with `graal3d = true`, `graal3d_pushterrain = true` (streamed terrain; without it a 5.12's first visit draws the terrain white) and the start level under the 3D spawn. A lab run on a real 5.12 (2026-11-26) had to copy the GServer-v2 layout's `world/3d/` into `files/` by hand. `--v2` keeps the GServer-v2 layout: `config/graal3dworld.txt`, the levels and gmap in `world/`, every 3D file in `world/3d/`, and `config/foldersconfig-3d.txt` (seihai-gserver-v2 `bin/docs/graal3d.md`, "Shipping a 3D world").
- `gen terrain --3d` and `gen 3d`, from the first real 5.12 runs of generated worlds: the colour bands follow the highest point that came out, not the requested reach (Peaks came out all sand); water cells are flat, so water no longer slopes up into valleys; the ground is one mesh when it fits 3DS's 16-bit counts, so no shading seam shows between levels; and the spawn point is on the flattest grass near the middle of the map, not in the water.
- `gen 3d` reads the original TerrainGenerator's gmaps: a comma-separated `HEIGHTMAP` with one height per level corner (`(WIDTH+1) x (HEIGHT+1)`), followed by `RANDOMSEEDS`. The corners are spread over the tiles by bilinear interpolation, since those levels carry no `HEIGHTS`. Streamed terrain's `heights.info` now names each texture with `.png`: the Linux 4.206 client given bare names drew the terrain white, then drew none.
- New tool `seihai-pw3d` (tools/pw3d; also `seihai-servertools pw3d`): a 2D playerworld folder as 3D worlds for seihai-gserver. Each level becomes one coloured `.3ds` ground (tile colours from a tileset, walls raised, water and lava sunk, chests, signs and baddies as simple shapes, link tiles tinted), each gmap one world and every other level a world named after it in `config/graal3dworlds/`, and a generated `PW3DWalk` weapon3d walks the player, stops it at walls, takes links (switching world with `g3dworld`) and shows signs. It writes `PW3D-REPORT.md` with what came across, what was approximated and what was dropped. Builds and tests on its own (`cargo test -p seihai-pw3d`). With `--objects` it reads what each tile shows from the object sets' stamp names and builds hills from cliffs, trees, roofed houses with doors in their own wall colour, shrubs and rocks; NPCs stand up as cut-outs of their own picture (found in the playerworld or `--images` folders), or as figures for ganis and body sheets.
- `seihai-pw3d`: each sign's words stand on a board over the sign in 3D capital letters, since a 3D client draws no 2D text or chat bubble over its own player. Boards fit between neighbouring signs, wrapping to up to 8 lines. On a real 5.12 the walker's camera stays in front of walls, walking runs at about 5 tiles a second by the clock, and a link taken in the first seconds after login still switches world on the server.
- New tool `seihai-edit3d` (tools/edit3d; also `seihai-servertools edit3d`): a standalone 3D level editor for seihai-gserver worlds. It opens `config/graal3dworld.txt` or any `config/graal3dworlds/<name>.txt` in a window with a live preview (the world's `.3ds` shapes, streamed terrain and water), places, moves, turns, copies and deletes objects, sets the spawn and sun, and raises, lowers, flattens, smooths and paints the terrain the `terrain` line names. The same edits and a PNG render work from the command line (`show`, `add`, `move`, `remove`, `spawn`, `terrain`, `render`). Every save keeps the world file as written apart from the changed lines, with a dated backup, and writes terrain chunks in the client's own encoding. `--renderer` hands the preview to another renderer. Tested on a real 5.12 (lab, 2026-11-26): it draws the edited worlds with ground heights matching, and a returning client downloads only the changed chunks. From that lab: `--ground` says when there is no terrain under the point (a seihai-pw3d world's floor is a shape), a brush that changes nothing saves nothing, and terrain backups go to `backups/` under the world folder instead of beside the terrain folder, where the server would serve them.
- New tool `seihai-regions` (tools/regions; also `seihai-servertools regions`): a big 3D overworld as a grid of region folders for seihai-gserver's `regions` world line. `split` cuts an existing world (a `terrain ... repeat WxH` large terrain, or a plain 16 x 16 one) into regions and writes the world file that uses them; `stats` prints objects per region and the densest spot within the scope reach against the 3584 objects a client holds; `demo` builds a whole test overworld (hills, fields and dense towns) for lab runs. Unit and CLI tests; the server side was walked on a real 5.12 (seihai-gserver #230).
- `seihai-pw3d`: house interiors (levels a link from the start level or a gmap leads to, and the levels linked on from them) are placed inside the world they are entered from, in rows well away from the land, with a `portal` line at each door, so walking through a door is a move in one world with no world switch. `--separate-interiors` keeps the old one-world-per-interior output. Needs seihai-gserver's `portal` line (#231) and `graal3d_scope` on.
- New tool `seihai-asset3d` (tools/asset3d; also `seihai-servertools asset3d`): converts glTF/GLB, OBJ (with its `.mtl`), STL and 3DS models, and pictures (as upright cards), into a `.3ds` and 8-bit PNG textures kept within what a real 5.12 draws (power-of-two textures at most 1024 px, lower-case names, alpha 0 or 255, 16-bit mesh chunks, at most 250 000 points a shape), with the front turned south and the asset stood on the ground. `add` puts them in a world folder's `files/` and lists them in `config/assets3d.txt`; `--colour-only` bakes textures into face colours for 4.20r8; `.dts`/`.dif` are copied after the 5.12's version checks; `check` tells what a 5.12 would have trouble with in a shape or picture; FBX, Collada, PLY, MD2/MD3 and ganis are refused with the reason.
- `scripts/community-worlds/build.sh` builds the 3D test worlds as community tarballs, one each with a README, licence note, build commits and checksums: the isle terrain playerworld, the regions overworld (8,192 units, 6 towns), the 20,164-object scoping grid, the interiors sample and the 40 redistributable conformance worlds. Reproducible: the same commits and date give the same checksums.
